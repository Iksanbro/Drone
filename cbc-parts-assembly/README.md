# CBC Parts Assembly

Мод для **NeoForge 1.21.1**. Делает две вещи:

1. Добавляет рецепты **последовательной сборки** (Create, sequenced assembly) для всех деталей пушек, кроме больших. Результат сразу готовый предмет-деталь: без литья, расплава и сверления.
2. Детали, поставленные **в выживании**, соединяются между собой так же, как в креативе. Пушку из них можно поставить на лафет и собрать редстоуном. Без мода сборка падает с ошибкой `Cannon must have exactly one opening and exactly one closed end`.

| | спаренная (Twin) и вертикальная спаренная автопушка: ствол, пружина, казённик, глушитель, дульный тормоз | чугун, бронза, сталь |
| | тяжёлая (Heavy) автопушка: ствол, дульный тормоз, глушитель, пружина, казённик, QF-казённик | чугун, бронза, сталь |

У `wrought_iron_medium_rocket_rail` в CBC:AT уже есть обычный рецепт верстака.

## Как устроен рецепт

Все рецепты строятся по одной схеме:

- **Старт:** слиток материала (`#c:ingots/<материал>`). Казённики стартуют с механизма своего материала: экстрактора казённика CBC или falling breech / экстрактора Neo Warfare.
- **Каждый цикл:**
  1. деплоер с **формой детали** (cast mould). Форма **не тратится** (`keep_held_item`), она задаёт, какая деталь получится;
  2. деплоер со слитком (у крупных деталей два слитка);
  3. пресс;
  4. у стволов, глушителей, тормозов и направляющих: пила (сверление канала). У пружин и recoil barrel: деплоер с пружиной.
- Число циклов подобрано так, чтобы расход металла был близок к литью (90 mB = 1 слиток). Например, ствол автопушки = 3 слитка, казённик = экстрактор + 3 слитка.

Пара «стартовый предмет + форма в деплоере» уникальна для каждой детали, поэтому Create не путает рецепты. Это проверяется и генератором, и тестом в игре.

Пока деталь в сборке, это предмет «*Деталь* (в сборке)» с полоской прогресса, как у механизма точности.

## Сборка пушки в выживании

1. Поставьте лафет (`cannon_mount`, для Neo Warfare подходит и `compact_mount`).
2. Ставьте детали **одного материала** в линию, глядя в сторону дула: казённик, пружина/recoil barrel/подшипник, затем стволы и насадки. При установке появятся частицы-искры: детали соединились.
3. Подайте редстоун на лафет для сборки.

Соединяются автопушки CBC, Twin/Heavy и ракетные подвесы CBC:AT, средние и роторные пушки Neo Warfare. Большие пушки мод не трогает.

Настройки в `<папка мира>/serverconfig/cbcparts-server.toml`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `connectPartsInSurvival` | `true` | соединять детали, поставленные в выживании |
| `connectPartsPlacedByMachines` | `true` | соединять и детали, поставленные механизмами (деплоер Create) |

Как это работает: у каждого семейства пушек в CBC и аддонах есть метод `onPlace`, который соединяет новый блок с соседями того же материала. Сами моды вызывают его только для игрока в креативе или если у материала включён `connects_in_survival`. Этот мод вызывает тот же метод после установки в выживании. Свойства материалов (прочность, вес, разброс) не меняются, штрафа сварки нет.

## Что ещё исправлено в аддонах

Найдено при разборе jar-файлов и подтверждено тестами на сервере:

- **Neo Warfare 0.0.6v** для 1.21.1 не содержит рецептов для своих форм и компонентов, а его block-рецепты литья и сверления лежат в папке с опечаткой (`block_recipies`) и не загружаются. Добавлены:
  - распил брёвен в 6 форм средних и роторных пушек;
  - сборка `*_mediumcannon_falling_breech`, `*_rotarycannon_breech_extractor` и `heavy_recoil_spring`.
- **CBC: Advanced Technologies 0.1.4c**: три рецепта форм не загружаются из-за ошибки формата (`twin_autocannon_barrel_mould`, `rocket_pod_rail_mould`, `rocket_pod_breech_mould`). Добавлены исправленные.
- У обоих аддонов loot-таблицы лежат по старому пути `loot_tables/`, и в 1.21.1 сломанный блок ничего не дропает. Для всех деталей и форм из этого мода добавлены таблицы: блок дропает сам себя.

## Сборка мода

Нужна Java 21.

```bash
cd cbc-parts-assembly
./gradlew build
```

Готовый jar: `build/libs/cbc-parts-assembly-1.21.1-1.0.0.jar`. Его нужно положить в `mods/` и на сервер, и клиентам.

Запуск игры для разработки (моды скачиваются автоматически): `./gradlew runClient`.

### Тесты

```bash
./gradlew runGameTestServer                  # с CBC:AT и Neo Warfare
./gradlew runGameTestServer -PwithoutAddons  # только Create Big Cannons
```

Тесты (`src/gametest`) поднимают сервер с настоящими модами и проверяют:

- каждый из 98 рецептов проходит все шаги через тот же поиск рецепта, что у деплоера, пресса и пилы Create, без путаницы с другими рецептами, и в конце даёт нужную деталь;
- автопушка CBC (сталь, бронза), Twin, Heavy, ракетный подвес, средняя (незерсталь) и роторная пушки, поставленные игроком в выживании, собираются на лафете;
- контроль: с выключенной настройкой та же пушка не собирается (`AssemblyException`);
- рецепты форм и компонентов и loot-таблицы на месте.

### Изменение рецептов

Все рецепты, модели, loot-таблицы и список предметов генерирует один скрипт. Список деталей и их стоимость задаются в нём:

```bash
python3 tools/generate_data.py
# с проверкой, что все ID существуют (папки с распакованными jar модов):
python3 tools/generate_data.py --validate path/to/cbc path/to/cbc_at path/to/neo_warfare
```

Сгенерированные файлы лежат в `src/generated/resources`, руками их не правят.

## Ограничения

- Внешний вид в клиенте (JEI, модели предметов «в сборке») не проверялся в запущенном клиенте: тесты серверные. Предмет «в сборке» использует модель готовой детали.
- Лицензия в `gradle.properties` указана как MIT. Поменяйте, если нужна другая.
